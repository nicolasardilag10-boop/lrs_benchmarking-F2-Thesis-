# Chromosome 21 Assembler Benchmark

This folder contains the Snakemake workflow for benchmarking long-read assemblers on human chromosome 21.

## Tools

Assemblers:

- Flye
- GoldRush
- Verkko
- ntLink

Execution:

- Snakemake controls the workflow.
- Docker runs the assembler software.

## Samples

- HG002
- HG003
- HG004

Technologies:

- PacBio HiFi
- Oxford Nanopore Technologies (ONT)

# Quick Start

## 1. Requirements

Check that Snakemake and Docker are available:

    snakemake --version
    docker --version
    docker ps

## 2. Configure the input data

Do NOT modify `Snakefile.assemblers`.

Copy the example settings file:

    cp benchmark_chr21_real/user_settings/input_data_path.example.yaml \
       benchmark_chr21_real/user_settings/input_data_path.local.yaml

Open it:

    nano benchmark_chr21_real/user_settings/input_data_path.local.yaml

Change only:

    input_root: "/path/to/final_normalized"

The input directory must contain:

    final_normalized/
    ├── HG002/
    ├── HG003/
    └── HG004/

with the expected PacBio HiFi and ONT chromosome 21 FASTQ files.

## 3. Dry-run

From `final_report_files/snakemake_assemblers_benchmarking/` run:

    snakemake \
      --snakefile benchmark_chr21_real/Snakefile.assemblers \
      --configfile benchmark_chr21_real/user_settings/input_data_path.local.yaml \
      --cores 4 \
      --dry-run \
      --printshellcmds

## 4. Run the workflow

After the dry-run succeeds:

    snakemake \
      --snakefile benchmark_chr21_real/Snakefile.assemblers \
      --configfile benchmark_chr21_real/user_settings/input_data_path.local.yaml \
      --cores 4 \
      --printshellcmds \
      --rerun-incomplete

# Important Files

`README.md`
: Instructions for running the workflow.

`Snakefile.assemblers`
: Main workflow. Normally do not edit this file.

`user_settings/input_data_path.example.yaml`
: Example user configuration.

`user_settings/input_data_path.local.yaml`
: Machine-specific input path. This file is not committed to Git.

`config/config.assemblers.yaml`
: Internal workflow settings.

`config/samples.assemblers.tsv`
: Expected samples and FASTQ filenames.

`config/containers.yaml`
: Docker image definitions.

For normal use on another server, the user should normally change only:

    user_settings/input_data_path.local.yaml
